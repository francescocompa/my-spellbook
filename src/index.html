Import 5etools data

This planner ships without spell data. Load a 5etools data export to fill it with spells, classes, subclasses, feats and species. Everything is parsed and stored in your browser — nothing is uploaded.

The .zip is the fastest path and needs nothing else. Loading individual JSON files works too: spells-*.json, class-*.json, feats.json, races.json, books.json, and include generated/gendata-spell-source-lookup.json or the spells won't know which classes can cast them.

Homebrew & Unearthed Arcana work too. Download any brew as JSON from the 5etools homebrew repository (D&D Beyond drops live there), or UA from the prerelease repository. Stage it alongside your other files — its books appear under “Homebrew & UA” in Sources.

One brew at a time — not the repository’s “Download ZIP”. That button hands you every brew plus all the artwork, several gigabytes of it, which no browser tab can open. Open the folder you want (spell/, class/, feat/, race/, subclass/…), click a single .json, then Download raw file. They are around 60 KB each. Reading files adds to what you already have, so you can collect them a few at a time.

Point this at an unzipped 5etools data folder, or a homebrew repository you cloned or extracted. It reads every .json once to learn which books are in there and how much each one holds, then throws the file away — only one file is ever in memory, so a library far too big to import as a .zip scans fine.

Repositories are filed by category — spell/, class/, collection/ — so one brew's content is spread across folders, and a “collection” brew keeps its spells in collection/ rather than spell/. That is why browsing for something like D&D Beyond Drops fails. This list is by book.

Artwork (_img/) is skipped. Nothing is stored until you tick books and import — and even then the “Your books” list below still decides what is kept.

Your books

A tick means this book is in my data. Unticking one you already have removes its content from this browser — the only way to get the space back. Nothing is written until you press Apply, and Apply says how many books it would remove before you do.

Your builds are never touched. A pick whose book is gone is flagged in the banner at the top of the app, not deleted — re-import that book and it resolves again.
